Interim Report

Bati Bank Credit Risk Probability Model

I am working on the Bati Bank Credit Risk Model Challenge, focusing on transaction-level behavioral data from the Xente platform to estimate customer credit risk when a direct default label is unavailable. The main goal is to build analytical and software engineering competencies through reproducible data pipelines, proxy target engineering, machine learning with MLflow, API deployment, Docker, and continuous integration.

This interim report summarizes progress made so far, methods applied, tools used, challenges encountered, and next steps planned for the final submission.

Objective

Implementation Steps

  • .gitignore for data, models, MLflow, and environment files.

Task 2: Data Profiling, Cleaning & EDA

Objective

Profile and explore the Xente transaction dataset for data quality and risk patterns.

Implementation Steps

  • 95,662 transactions, 3,742 customers; no missing values in raw columns.
  • notebooks/eda.ipynb and src/eda.py helpers.
  • Heavy-tailed monetary features; ~0.2% fraud proxy rate.

Task 3: Feature Engineering & Proxy Target (RFM)

Objective

Build customer-level features and binary proxy target is_high_risk.

Implementation Steps

  • Aggregates, time features, categorical modes in src/data_processing.py.
  • RFM + K-Means (k=3) → least engaged cluster = high risk.
  • WoE/IV analysis module in src/woe_iv.py.
Figure 6: RFM customer segments (proxy target)

Outcome

Proxy pipeline tested and documented; modeling dataset exportable to data/processed/.

Task 4: Model Training & MLflow

Objective

Train and compare classifiers with hyperparameter tuning and experiment tracking.

  • Logistic Regression, Decision Tree, Random Forest, Gradient Boosting.
  • RandomizedSearchCV; metrics: accuracy, precision, recall, F1, ROC-AUC.
  • Outputs: model_comparison.csv, best_model_summary.json.

Task 5: FastAPI & Docker

  • /health and /predict with Pydantic validation.
  • Returns risk_probability and risk category.
  • Dockerfile + docker-compose with health checks.

Task 6: Testing & CI

  • 42+ pytest tests; Ruff lint/format on push to main.

Next Steps

  • Finalize model training and comparison for final report.
  • Interpretability analysis (SHAP / coefficients).
  • Peer-test API and Docker; prepare final PDF for Bati Bank.

Conclusion

The project has a solid foundation: EDA, proxy target, ML pipeline, API, Docker, and CI/CD. Ready for final model selection, validation, and stakeholder reporting.
