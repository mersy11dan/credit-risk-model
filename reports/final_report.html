1. Executive Summary

Bati Bank requires credit risk scoring where bureau data is thin and direct default labels are unavailable. This project builds a production-ready pipeline on Xente transaction data: EDA, RFM proxy targeting, four tuned ML models, MLflow tracking, FastAPI + Docker deployment, and CI with 42 unit tests.

Best model: Gradient Boosting (test ROC-AUC = 0.99995). Recommendation: Use GB for ranking; maintain Logistic Regression + WoE for regulatory narrative; validate against true defaults before automated lending decisions.

2. Business Problem

The bank must estimate probability of failure to repay using digital transaction behavior. Success requires ranked risk scores, documented methodology, API integration, and improved loss rates without excluding creditworthy thin-file customers.

3. Basel II Considerations and Regulatory Context

Basel II IRB standards require transparent, documented, and stable PD estimation. For Bati Bank this means:

  • Interpretability — WoE/IV and logistic regression for audit dialogue
  • Documentation — data lineage, proxy assumptions, monitoring plans
  • Challenge models — four algorithms compared under identical splits

6. Key Insights from EDA

  • Rare fraud at transaction level (0.20%) — use PR-AUC, not accuracy alone
  • Extreme outliers — cap for dashboards; robust scaling for ML
  • Skewed customer activity — median 7 txns vs mean 25.6
  • Product concentration — airtime + financial_services dominate

24. Business Recommendations

  1. Two-model strategy: GB for ranking, logistic/WoE for regulation
  2. Manual review for inactive low-frequency segment
  3. Monthly PSI and fraud-rate monitoring
  4. Enrich with bureau and income data
  5. Fairness review before scale-up

25–27. Risks, Future Work & Conclusion

Primary risk: proxy ≠ default. Future: SHAP, out-of-time validation, calibration, PSI dashboard, true default labels. This project provides a governed foundation for alternative-data credit scoring at Bati Bank.
